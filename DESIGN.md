# Scout visual system

The app uses a modern dark "bento" system: rounded tiles on a near-black canvas, with one mint action colour and a mint-to-cyan gradient reserved for the logo mark and key data. Researchers still read dense evidence for long sessions, so body text stays high contrast (every text element measures at least 4.5:1) and secondary text never drops below 11px.

Tokens live in `src/styles.css`: canvas `--bg` #090c0e, surfaces `--surface` #11171a and `--surface-2` #161e22, text `--ink` / `--muted` / `--subtle`, action `--primary` #7cf5c8 with `--on-primary` text, tint `--primary-light`, second accent `--accent-2` #5ad1ff, statuses `--green` / `--amber` / `--red`, radii `--radius-card` 20px and `--radius-control` 10px. Colours that are not tokens keep their hue so status meanings carry across screens. UI text uses locally bundled Geist; metadata and keyboard hints use Geist Mono; numbers use tabular figures.

A floating rounded sidebar sits beside a glassy sticky top bar, spacious page headings, metric strips split into separate tiles, and panels as 20px tiles with hairline borders rather than decorative shadows. Buttons are pills: mint for the primary action, quiet surface for the rest. Inputs sit darker than their card and show a mint focus ring. The shell and component layer lives in `src/theme.css`, loaded last. Motion uses brief opacity/transform changes and honors reduced motion.

The Leads workspace uses five columns: store, main opportunity, contact and next step, preceded by selection. A compact directory toolbar keeps filters above the results, with secondary saved views and sorting grouped below. Initial avatars identify stores without external image requests. Long emails stay on one line with a full-address tooltip and copy action. Opportunity strength stays separate from outreach review. At narrow component widths, rows become structured records with full-width contact information. Use a four-point spacing scale, 24px section gutters (16px on phones), readable 12–14px content, and 11px secondary metadata. The lead panel presents a compact three-part summary and one prominent contact, with additional contacts and assessment scope disclosed on demand. Detailed evidence retains its reading space. Component styles live in `src/leads.css`.

The research workspace uses a horizontal run chooser and a dark teal task map with an inspector and synchronized timestamped feed. The default desktop Neural model uses a Three.js neuron mesh (2,000 by default, up to 10,000), labeled stage regions, direct neuron picking, hover highlights and orbit/zoom controls. Its selected region stays synchronized with the task inspector and feed. The Task map tab retains the detailed hierarchy: Scout's luminous Three.js core branches through curved SVG pathways into four stable stage groups, each containing actual task nodes and result controls. Labels identify individual samples, pages and report operations. Mint indicates active/completed work, amber retry, and coral failure, always paired with readable status text. The current-work banner makes the resource, action and timing visible. Task results retain measurements and findings in their inspector. Feed entries and keyboard-accessible task buttons select the same stable task identity.

Every traveling signal comes from a newly observed worker dispatch or result. Only active/waiting tasks pulse continuously; idle/completed task maps settle without ambient motion. The Neural model has explicit Animate model and Send visual pulse exploration controls, labeled as visual-only work and using cyan signals to distinguish them from real worker events. Follow live activity is explicit and manual selections remain pinned. Scrollable stage history can expand while node insertion order and stage anchors remain stable. Pause animation leaves data updates running. Reduced motion and small screens use a clear 2D task list. Desktop 3D combines a neural core with restrained user-controlled perspective, zoom, reset and expansion. The renderer is lazy and stops motion offscreen/hidden. Previews carry a persistent fictional-data notice. Styles live in `src/research.css` and `src/neural-network.css`.

PageSpeed audit scores use four circular SVG gauges with Lighthouse's red (#f33), orange (#fa3) and green (#0c6) strokes, pale fills and darker readable numerals. Score ranges are 0–49, 50–89 and 90–100; missing scores use a gray dash. Mobile/Desktop buttons switch the four categories together. Lead details require three comparable tests for each median; the research workspace explicitly shows the latest saved sample. Both show the recorded time in Philippine time. Gauge rows collapse to two columns on narrow containers. The shared component is `src/components/PageSpeedAudit.tsx`, with styles in `src/pagespeed.css`.


The semantic neural model separates its faint background brain mesh from task-linked foreground hubs, task neurons and result endpoints. Primary, branch and result links have distinct screen-space weights; selection emphasizes the complete route. Shared curved path samples drive both drawn links and signal motion. Upright HTML labels follow their projected 3D anchors with leader lines and measured collision avoidance. Overview/Stage/Task focus progressively disclose stable task positions; larger histories remain accessible through clusters, the full Task map and a native task selector. The task inspector leads with returned measurement values in readable Lighthouse colors. Model styles remain in `src/neural-network.css`; topology and geometry are in `src/components/neural-task-graph.ts`.

The neural observatory adds a soft additive tissue layer whose selected region brightens while other regions remain visible for depth. A bounded shader wave responds to a visual pulse; continuous sweeps run only during explicitly labeled exploration. The Scout core uses three thin orbital arcs and a counter-rotating inner structure. Task selection produces a short cyan route preview, while newly observed worker signals retain their mint-white color. Explore motion is available above the canvas; auto orbit and tissue visibility are independent controls. Stage label tracks summarize actual completed/skipped tasks and issues. Pause and offscreen/hidden behavior govern every continuous effect; small screens and reduced-motion preferences retain the native task map.

The Task map uses a branching workflow board with a measured central trunk, four stage groups, and larger task rows. A small SVG Scout engine keeps this view lightweight. Task rows show explicit status, source URL and a separate result control; performance results retain Lighthouse score colors. Search and All/Running/Needs attention filters apply to the retained task history. Initial stage previews show two tasks, preserve the selected/current task, and reveal four more at a time. Curved connections recalculate on resize, collapse and history expansion. Live dispatch/return signals are mint-white; user-invoked flow previews and selection traces are cyan and explicitly labeled. The same stable task ID selects the board, inspector, neural view and activity feed. Narrow layouts use one stage per row; pause, offscreen and reduced-motion preferences govern animation.

Scout core combines all five Core lab studies. Photon rings retain a 35% gap at rest, accelerate over five seconds of active execution into continuous luminous beams, and reopen over 3.2 seconds when work stops. No orbiting beads are used. Bounded, irregular collision blooms appear at actual 3D beam intersections; they are labeled as visual effects and never imply a result. Three selectable palettes (Polar current, Solar tide, Orchid engine) give distinct roles to the inner structure and orbital beams. The core itself has ten named work-state colors derived from current execution, never the selected historical task. Newly observed result signals follow their real task routes into the core and produce a brief intake halo. Four evidence markers illuminate only for recorded measurements, pages, public contacts, and reports (discovery uses search, verified stores, contact and queued audits). Matching accessible evidence controls open saved evidence. Task-map SVG uses the same palette, state, evidence and drive timing without another WebGL context. Pausing freezes transient visuals while task data continues updating; offscreen/hidden and reduced-motion rules govern both renderers. Small screens default to the task map and offer an explicit Use 3D control; reduced motion retains the steady 2D view.

The live neural tissue defaults to 2,000 visual neurons, with auto orbit on, with local spatial-hash connections. The background uses two buffered GPU draws (points and lines), smaller depth-sensitive dots, and density-scaled line opacity to preserve task-label contrast. An explicit 2,000 / 5,000 / 10,000 density selector changes only the visual mesh. Semantic tasks, evidence and actual job counts stay separate. Mesh generation happens inside the lazy renderer, and background picking is disabled so pointer interactions remain focused on real task nodes.

Neural tissue uses ten stable randomized dot sizes (1.5–10.4 CSS pixels), with weights of 38%, 24%, 15%, 9%, 5.5%, 3.5%, 2.2%, 1.4%, 0.9%, and 0.5%. Most neurons are fine points; large luminous hubs are rare. Integer hashing fixes each neuron's size across renders and density changes. A single per-point GPU attribute drives the variety without adding draw calls or continuous CPU work.
